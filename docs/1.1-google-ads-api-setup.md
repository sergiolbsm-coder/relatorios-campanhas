# 1.1 — Google Ads API: projeto GCP, OAuth2 client e developer token

Checklist para fechar o item 1.1 do roadmap. Cada passo abaixo precisa do seu
login Google (sergiolbsm@gmail.com) com acesso admin ao Google Ads das duas
contas (Instituto da Liderança `7613902765`, Associação de Luto União
`4001041542` via MCC "Sergio Moura"). Marque cada `[ ]` ao concluir.

---

## Passo 1 — Criar o projeto no Google Cloud

1. Acesse https://console.cloud.google.com/projectcreate
2. Nome do projeto: `analise-campanhas` (ou outro nome seu — só anote, vamos
   usar o mesmo projeto para GA4 e GMB depois)
3. Organização/local: deixe o padrão, a não ser que sua conta já tenha uma
   organização específica
4. Clique **Criar** e espere o projeto ficar pronto (uns 30s)

`[ ]` Projeto criado. Anote o **Project ID** (aparece no topo do console).

## Passo 2 — Ativar a Google Ads API

1. Com o projeto selecionado, acesse
   https://console.cloud.google.com/apis/library/googleads.googleapis.com
2. Clique **Ativar** (Enable)

`[ ]` API ativada.

## Passo 3 — Configurar a tela de consentimento OAuth

1. Acesse https://console.cloud.google.com/apis/credentials/consent
2. Tipo de usuário: **Externo** (a menos que você tenha Google Workspace com
   organização própria — aí pode usar Interno)
3. Preencha:
   - Nome do app: `Análise de Campanhas` (ou o nome que preferir)
   - E-mail de suporte: sergiolbsm@gmail.com
   - E-mail do desenvolvedor: sergiolbsm@gmail.com
4. Salve e continue pelas telas seguintes (escopos: pode pular, adicionamos
   via código depois; usuários de teste: adicione sergiolbsm@gmail.com)
5. **Não precisa publicar o app** — como "Em teste" ele já funciona para
   as contas que você adicionar como testadoras (limite de 100, mais que
   suficiente aqui)

`[ ]` Tela de consentimento configurada, sergiolbsm@gmail.com como usuário de teste.

## Passo 4 — Criar as credenciais OAuth2 (client ID)

1. Acesse https://console.cloud.google.com/apis/credentials
2. **Criar credenciais** → **ID do cliente OAuth**
3. Tipo de aplicativo: **App para computador** (Desktop app) — é o tipo certo
   para rodar o fluxo de autorização localmente e gerar o refresh token
4. Nome: `analise-campanhas-desktop`
5. Clique **Criar**
6. Vai aparecer um popup com **Client ID** e **Client Secret** — copie os dois

`[ ]` Client ID e Client Secret copiados para `.env`:
```
GOOGLE_ADS_CLIENT_ID=<cole aqui>
GOOGLE_ADS_CLIENT_SECRET=<cole aqui>
```

## Passo 5 — Gerar o refresh token

Use o script que preparei em
[`etl/scripts/generate_google_ads_refresh_token.py`](../etl/scripts/generate_google_ads_refresh_token.py).
Ele abre uma janela do navegador, você loga com sergiolbsm@gmail.com e
autoriza — o script imprime o refresh token no terminal.

```bash
cd analise-campanhas
python3 -m venv .venv && source .venv/bin/activate
pip install google-auth-oauthlib
python3 etl/scripts/generate_google_ads_refresh_token.py
```

`[ ]` Refresh token gerado e colado em `.env`:
```
GOOGLE_ADS_REFRESH_TOKEN=<cole aqui>
```

## Passo 6 — Solicitar o developer token

1. Acesse sua conta Google Ads em https://ads.google.com (com o MCC "Sergio
   Moura", já que é ele que dá acesso às duas contas do projeto)
2. Menu **Ferramentas e Configurações → Configuração → API Center**
   (em inglês: Tools & Settings → Setup → API Center)
3. Se ainda não existir, clique para gerar um developer token — ele nasce em
   nível **Test** (só funciona com contas de teste do Google Ads, não com as
   contas reais do projeto)
4. Para usar as contas reais (Instituto da Liderança, Luto União), é preciso
   solicitar acesso **Básico** ou **Standard**: preencha o formulário de
   solicitação dentro do próprio API Center explicando o uso (ferramenta
   interna de BI para consolidar métricas das próprias contas geridas pelo
   MCC). **A aprovação da Google pode levar de alguns dias a ~2 semanas** —
   vale fazer esse pedido agora e seguir com os outros itens da Fase 1
   enquanto espera.

`[ ]` Developer token (nível Test) copiado para `.env`:
```
GOOGLE_ADS_DEVELOPER_TOKEN=<cole aqui>
```
`[ ]` Solicitação de nível Básico/Standard enviada (anote a data: __________)

## Passo 7 — Login customer ID (MCC)

Esse é o customer ID do MCC "Sergio Moura" (sem hífens), necessário porque a

`[ ]` `GOOGLE_ADS_LOGIN_CUSTOMER_ID=<ID do MCC, sem hífens>` no `.env`

## Critério de pronto deste item

Todas as 5 variáveis abaixo preenchidas em `.env`:

```
GOOGLE_ADS_CLIENT_ID=
GOOGLE_ADS_CLIENT_SECRET=
GOOGLE_ADS_REFRESH_TOKEN=
GOOGLE_ADS_DEVELOPER_TOKEN=
GOOGLE_ADS_LOGIN_CUSTOMER_ID=
```

Com developer token nível **Test**, já dá para validar o script de extração
(2.1) contra uma conta de teste. Para puxar dado real das contas do projeto,
é preciso a aprovação de nível Básico do Passo 6 — enquanto isso não sai,
seguimos para 1.2 (Meta Ads) e 1.4 (GA4) em paralelo, que não têm essa
dependência de aprovação manual da Google.

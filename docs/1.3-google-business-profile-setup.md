# 1.3 — Google Business Profile API (Google Meu Negócio)

Checklist para fechar o item 1.3. **Atenção**: diferente do GA4, o acesso à
Business Profile API passa por uma **aprovação manual da Google** que não é
automática (Google restringiu isso desde 2020 por causa de abuso/spam) — vale
disparar o pedido do Passo 1 o quanto antes e seguir com outras tarefas
enquanto espera.

> **Nota**: esses IDs vieram do Supermetrics e têm o formato
> `{account_id}_{location_id}`. A Business Profile API oficial usa um
> formato próprio de recurso (`accounts/{id}/locations/{id}`) — os números
> devem ser os mesmos, mas vamos **confirmar via API no Passo 5**, não
> assumir que o formato bate 100%.

## Passo 1 — Solicitar acesso à API (fazer isto primeiro — é o gargalo)

1. Preencha o formulário oficial de solicitação de acesso:
```
https://support.google.com/business/contact/api_default
```
2. Informe: nome do projeto, e-mail (sergiolbsm@gmail.com), e descreva o uso
   como "ferramenta interna de BI para consolidar métricas das próprias
   fichas de Google Meu Negócio administradas" — deixe claro que é uso
   próprio, não um produto para terceiros
3. Aguarde o e-mail de aprovação (pode levar de dias a poucas semanas)

`[ ]` Solicitação enviada em: __________ `[ ]` Aprovação recebida em: __________

## Passo 2 — Ativar as APIs no Google Cloud

Com a aprovação em mãos, no mesmo projeto (`campanha-instituto`):

1. https://console.cloud.google.com/apis/library/mybusinessbusinessinformation.googleapis.com
   → **Ativar**
2. https://console.cloud.google.com/apis/library/mybusinessaccountmanagement.googleapis.com
   → **Ativar**
3. https://console.cloud.google.com/apis/library/businessprofileperformance.googleapis.com
   → **Ativar** (essa é a que traz as métricas — views, buscas, ações)

`[ ]` As 3 APIs ativadas.

## Passo 3 — Reaproveitar o OAuth client do Google Ads (ou criar um novo)

Você já tem um OAuth Client ID/Secret do item 1.1 (tipo "App para
computador"), no mesmo projeto. Pode reaproveitar o mesmo client — só muda o
escopo de autorização. Se preferir isolar, crie um novo client seguindo o
Passo 4 do guia [1.1](1.1-google-ads-api-setup.md).

`[ ]` Client ID/Secret definidos (reaproveitados ou novos):
```
GBP_CLIENT_ID=<cole aqui>
GBP_CLIENT_SECRET=<cole aqui>
```

## Passo 4 — Gerar o refresh token (escopo Business Profile)

```bash
cd /Users/sergiomoura/Claude/analise-campanhas
source .venv/bin/activate
export GBP_CLIENT_ID="<seu client id>"
export GBP_CLIENT_SECRET="<seu client secret>"
python3 etl/scripts/generate_gbp_refresh_token.py
```

Igual ao Passo 5 do guia 1.1: abre o navegador, você loga com
sergiolbsm@gmail.com e autoriza. Se aparecer o erro `access_denied` de
testador, é o mesmo problema de antes — adicione sergiolbsm@gmail.com em
**Usuários de teste** na tela de consentimento OAuth desse projeto (ver
[troubleshooting do guia 1.1](1.1-google-ads-api-setup.md#troubleshooting)).

`[ ]` Refresh token salvo no `.env`:
```
GBP_REFRESH_TOKEN=<cole aqui>
```

## Passo 5 — Descobrir os IDs reais e validar

```bash
python3 etl/scripts/test_gbp_access.py
```

Esse script lista as contas e locais que a API enxerga de verdade — use pra
conferir se os IDs batem com os do Supermetrics na tabela do topo deste
documento. Se não baterem exatamente, atualize `config.yaml` com os IDs
corretos (a API é a fonte de verdade, não o Supermetrics).

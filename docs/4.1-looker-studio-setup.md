# 4.1 — Dashboard: Google Sheets + Looker Studio

**Decisão (26/08/2026)**: dashboard via **Looker Studio conectado a uma
planilha Google**. Looker Studio não conecta em SQLite direto, então o
fluxo fica:

```
db/analise_campanhas.db  --(export_to_sheets.py)-->  Google Sheets  -->  Looker Studio
```

O `export_to_sheets.py` sobrescreve a aba `dados_diarios` inteira a cada
execução (não é incremental) — simples e suficiente pro volume atual (~1.100
linhas). Fica granular por dia/marca/canal/campanha — deixamos o Looker
Studio fazer as agregações e comparativos de período (ele tem isso nativo),
em vez de pré-calcular aqui.

---

## Passo 1 — Ativar a Google Sheets API

No mesmo projeto GCP (`campanha-instituto`):
```
https://console.cloud.google.com/apis/library/sheets.googleapis.com
```
Clique **Ativar**.

`[ ]` API ativada.

## Passo 2 — Gerar um refresh token com escopo de Sheets

Reaproveita o mesmo Client ID/Secret do Google Ads (Passo 4 do guia 1.1) —
não precisa criar um novo OAuth client.

```bash
cd /Users/sergiomoura/Claude/analise-campanhas
source .venv/bin/activate
pip install gspread
export GOOGLE_ADS_CLIENT_ID="<mesmo do .env>"
export GOOGLE_ADS_CLIENT_SECRET="<mesmo do .env>"
python3 etl/scripts/generate_sheets_refresh_token.py
```

Login com sergiolbsm@gmail.com (já está na lista de testadores desse
projeto, não deve repetir os erros do 1.1).

`[ ]` Refresh token salvo no `.env`:
```
GOOGLE_SHEETS_REFRESH_TOKEN=<cole aqui>
```

## Passo 3 — Exportar os dados

```bash
python3 etl/export_to_sheets.py
```

Na primeira execução, sem `GOOGLE_SHEETS_SPREADSHEET_ID` definido, o script
**cria uma planilha nova** na sua conta Google e imprime o ID e o link.
Copie o ID pro `.env`:
```
GOOGLE_SHEETS_SPREADSHEET_ID=<cole aqui>
```
Nas próximas vezes, rodando com essa variável já definida, ele atualiza a
mesma planilha em vez de criar outra.

## Passo 4 — Conectar o Looker Studio

1. Acesse https://lookerstudio.google.com
2. **Criar** → **Fonte de dados** → **Planilhas Google**
3. Selecione a planilha criada no Passo 3, aba `dados_diarios`
4. **Conectar** → **Criar relatório**
5. Looker Studio já detecta `date` como dimensão de data — isso libera os
   controles nativos de **intervalo de datas** e **comparação de período**
   (WoW/MoM do item 4.4), sem precisar calcular nada manualmente

`[ ]` Relatório criado, campo `date` reconhecido como tipo Data.

## Reexecutar quando os dados mudarem

Sempre que rodar novas extrações (Fase 2) + `load_to_sqlite.py` (Fase 3),
rode `export_to_sheets.py` de novo pra refletir no Looker Studio — a
automação disso é o item 5.3 (atualização automática), ainda não feita.
